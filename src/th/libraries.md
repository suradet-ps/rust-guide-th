# ไลบรารี

## คลังเก็บดีเพนเดนซี

การจัดการไลบรารีภายนอกถูกรวมไว้ในเครื่องมือ `Cargo` โดยมีหลายวิธีในการระบุแหล่งที่มาของไลบรารีเหล่านี้ ซึ่งบางวิธีนำเสนอไว้ด้านล่างนี้

สิ่งสำคัญที่ต้องทราบคือ การติดตามเวอร์ชันของไลบรารีเหล่านี้อย่างแม่นยำเป็นเงื่อนไขสำคัญยิ่งต่อความปลอดภัยของซอฟต์แวร์ที่เขียนด้วย Rust ข้อกำหนดนี้ปรากฏอยู่ในกฎ [DENV-CARGO-LOCK](devenv.md#DENV-CARGO-LOCK)

### เครต

นอกเหนือจากไลบรารีมาตรฐานแล้ว Rust ยังมีวิธีนำเข้าไลบรารีอื่น ๆ เข้าสู่โปรเจกต์ได้อย่างง่ายดายด้วย `cargo`
ในระบบนิเวศของ Rust ไลบรารีเหล่านี้รู้จักกันในชื่อ *เครต (crate)* และนำเข้าจากคลังเก็บ
ส่วนกลางของคอมโพเนนต์โอเพนซอร์ส

ตัวอย่างการประกาศดีเพนเดนซีในไฟล์ `Cargo.toml`:

```toml
[dependencies]
mdbook = { version = "0.4.52" }
anyhow = "1.0.99"
clap = { version = "4.5.47", features = ["derive"] }
markdown = { version = "1.0.0", features = ["serde"] }
semver = "1.0.26"
serde_json = "1.0.143"
serde = "1.0.219"
```

คลังเก็บเริ่มต้นคือ [`crates.io`] นอกจากนี้ยังสามารถใช้[รีจิสทรีของคุณเอง (your own registry)](https://doc.rust-lang.org/cargo/reference/registries.html)ได้ด้วย

[`crates.io`]: https://crates.io

### ดีเพนเดนซีจาก Git

ดีเพนเดนซีแต่ละรายการในไฟล์ `Cargo.toml` ยังสามารถอ้างอิงถึง[คลังเก็บ GIT](https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html#specifying-dependencies-from-git-repositories)ได้ด้วย ตัวอย่างเช่น:

```toml
[dependencies]
regex = { git = "https://github.com/rust-lang/regex.git" }
```

สามารถระบุเวอร์ชันที่ต้องการได้อย่างละเอียดยิ่งขึ้น โดยระบุเป็นแบรนช์ (branch) แท็ก (tag) หรือแฮชของคอมมิต (commit hash)

[ระบบล็อกดีเพนเดนซี](devenv.md#cargo) ทำงานได้แม้ในกรณีของคลังเก็บ GIT: หากดีเพนเดนซีไม่ได้ระบุคอมมิตใดโดยเฉพาะ คอมมิตล่าสุดที่ตรงกับเงื่อนไขในไฟล์ `Cargo.toml` จะถูกดึงมาในระหว่างการคอมไพล์ครั้งแรกและบันทึกไว้ในไฟล์ `Cargo.lock` การคอมไพล์ครั้งต่อ ๆ ไปทั้งหมดจะใช้คอมมิตเดียวกัน (เว้นแต่ไฟล์ `Cargo.lock` จะถูกอัปเดต)

## ความปลอดภัยของดีเพนเดนซี

ไม่ว่าจะใช้วิธีใดในการดึงดีเพนเดนซี (*เครต* หรือคอมมิตจาก GIT) หากดีเพนเดนซีเหล่านี้มาจากองค์กรภายนอก ดีเพนเดนซีเหล่านั้นต้องได้รับการตรวจสอบประเมิน

<div class="reco" id="LIBS-VETTING-DIRECT" type="กฎ" title="การตรวจสอบประเมินดีเพนเดนซีโดยตรงจากบุคคลที่สาม">

ดีเพนเดนซีโดยตรงจากบุคคลที่สามแต่ละรายการ ต้องได้รับการตรวจสอบประเมินอย่างเหมาะสม และการตรวจสอบประเมินแต่ละครั้งต้องบันทึกไว้เพื่อติดตาม

</div>

สำหรับดีเพนเดนซีทางอ้อม (transitive dependency) แนะนำให้ตรวจสอบประเมินแยกแต่ละรายการเช่นกัน

<div class="reco" id="LIBS-VETTING-TRANSITIVE" type="ข้อเสนอแนะ" title="การตรวจสอบประเมินดีเพนเดนซีทางอ้อมจากบุคคลที่สาม">

ดีเพนเดนซีจากบุคคลที่สามแต่ละรายการ ควรได้รับการตรวจสอบประเมินอย่างเหมาะสม และการตรวจสอบประเมินแต่ละครั้งควรบันทึกไว้เพื่อติดตาม

</div>

## เครื่องมือสำหรับตรวจสอบประเมินดีเพนเดนซี

### Cargo-outdated

เครื่องมือ [cargo-outdated] ช่วยให้สามารถจัดการเวอร์ชันของดีเพนเดนซีได้อย่างง่ายดาย

สำหรับเครตที่ระบุ เครื่องมือนี้จะแสดงรายการเวอร์ชันปัจจุบันของดีเพนเดนซี (โดยใช้
`Cargo.toml`) พร้อมทั้งตรวจสอบเวอร์ชันล่าสุดที่เข้ากันได้ และเวอร์ชันล่าสุด
โดยทั่วไปด้วย

<div class="reco" id="LIBS-OUTDATED" type="กฎ" title="ตรวจสอบดีเพนเดนซีที่ล้าสมัย (cargo-outdated)">

ต้องใช้เครื่องมือ `cargo-outdated` เพื่อตรวจสอบสถานะของดีเพนเดนซี จากนั้น
ดีเพนเดนซีที่ล้าสมัยแต่ละรายการ ควรได้รับการอัปเดต หรือไม่ก็ต้อง
แสดงเหตุผลประกอบการเลือกใช้เวอร์ชันนั้น

</div>

[cargo-outdated]: https://github.com/kbknapp/cargo-outdated

### Cargo-audit

เครื่องมือ [Cargo-audit] ช่วยให้สามารถตรวจสอบช่องโหว่ด้านความปลอดภัย
ที่ถูกรายงานต่อ RustSec Advisory Database ได้อย่างง่ายดาย

<div class="reco" id="LIBS-AUDIT" type="กฎ" title="ตรวจสอบรายงานช่องโหว่ด้านความปลอดภัยของดีเพนเดนซี (cargo-audit)">

ต้องใช้เครื่องมือ `cargo-audit` เพื่อตรวจสอบช่องโหว่ที่รู้จักใน
ดีเพนเดนซี

</div>

[cargo-audit]: https://crates.io/crates/cargo-audit
