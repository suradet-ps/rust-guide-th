# การดำเนินการกับจำนวนเต็ม {#chapter-integer}

แม้ว่า Rust จะดำเนินการตรวจสอบการล้น (overflow) ที่อาจเกิดขึ้นกับจำนวนเต็มอยู่บ้าง แต่ก็ควรใช้ความระมัดระวังเมื่อดำเนินการทางคณิตศาสตร์กับจำนวนเต็ม

โดยเฉพาะอย่างยิ่ง โปรดทราบว่าโปรไฟล์การคอมไพล์ (compilation profile) (โดยทั่วไปคือ *dev* ซึ่งเป็นการสร้างแบบ debug ที่เป็นค่าเริ่มต้น หรือ *release* ซึ่งเป็นการสร้างแบบปรับประสิทธิภาพมาตรฐาน) เปลี่ยนแปลงพฤติกรรมการล้นของจำนวนเต็ม ในคอนฟิกูเรชัน *dev* การล้นทำให้โปรแกรมหยุดทำงาน (`panic`) ในขณะที่คอนฟิกูเรชัน *release* ค่าที่คำนวณได้จะถูกตัดอย่างเงียบ ๆ ให้เหลือตามจำนวนบิตของชนิดข้อมูลตัวเลข ซึ่งให้ความหมายแบบการวนกลับค่า (wrap-around)

<div class="note">

พฤติกรรมการล้นของจำนวนเต็มสามารถกำหนดได้อย่างชัดเจนด้วยตัวเลือกการคอมไพล์ `-C overflow-checks=true` (หรือ `false`)
นอกจากนี้ยังแก้ไขได้ในนิยามโปรไฟล์ใน `Cargo.toml`:

```toml
[profile.release]
overflow-checks = true  # enable overflow checks in release builds
```

</div>

เมื่อการล้นสามารถเกิดขึ้นได้ พฤติกรรมดังกล่าวสามารถทำให้ชัดเจนได้โดยใช้เมธอดเฉพาะหรือใช้ชนิดข้อมูลตัวห่อ (wrapper type) เฉพาะ

เมธอดเหล่านี้มีรูปแบบ `<mode>_<op>` โดย `<mode>` ได้แก่ `checked`, `overflowing`, `wrapping` หรือ `saturating` และ `<op>` ได้แก่ `add`, `mul`, `sub`, `shr` เป็นต้น ความหมายเชิงการทำงาน (semantics) มีดังนี้:

- `checked_<op>` คืนค่า `None` ในกรณีที่เกิดการล้น
  
  ตัวอย่างเช่น `255u8.checked_add(1)` คืนค่า `None`
- `overflowing_<op>` คืนค่าทั้งผลลัพธ์ที่อาจถูกวนกลับค่าและค่าบูลีนที่ระบุว่าเกิดการล้นขึ้นหรือไม่
  
  ตัวอย่างเช่น `255u8.overflowing_add(1)` คืนค่า `(0, true)`
- `wrapping_<op>` คืนค่าผลลัพธ์ที่วนกลับค่าเสมอ
  
  ตัวอย่างเช่น `255u8.wrapping_add(1)` คืนค่า `0`
- `saturating_<op>` คืนค่าผลลัพธ์ที่อิ่มตัว (saturating) เสมอ
  
  ตัวอย่างเช่น `255u8.saturating_add(1)` คืนค่า `255`

ชนิดข้อมูลตัวห่อได้แก่ `Wrapping<T>` และ `Saturating<T>` (จาก `std::num`) โดย `T` เป็นชนิดข้อมูลจำนวนเต็ม ชนิดแรกให้ความหมายแบบการวนกลับค่าสำหรับการดำเนินการทางคณิตศาสตร์ทั้งหมด ส่วนชนิดหลังให้ความหมายแบบอิ่มตัว (saturation) เมื่อค่าถูกห่อแล้ว การดำเนินการที่ตามมาทั้งหมดจะถูกกระทำตามความหมายที่กำหนด


เมื่อการดำเนินการทางคณิตศาสตร์สามารถก่อให้เกิดการล้นได้ ต้องไม่ใช้โอเปอเรเตอร์ทั่วไปโดยตรง
แต่ต้องใช้เมธอดเฉพาะ เช่น `checked_<op>`, `overflowing_<op>`, `wrapping_<op>` หรือ `saturating_<op>` หรือชนิดข้อมูลตัวห่อเฉพาะ เช่น `Wrapping` หรือ `Saturating` เพื่อให้แน่ใจว่าพฤติกรรมมีความชัดเจนและสม่ำเสมอไม่ว่าโปรไฟล์การคอมไพล์จะเป็นเช่นใด

</div>
