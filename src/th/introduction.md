# บทนำ

[Rust](https://www.rust-lang.org) เป็นภาษาหลายกระบวนทัศน์ (multi-paradigm) ที่มุ่งเน้นความปลอดภัยของหน่วยความจำ (memory safety)

ภาษานี้มีเป้าหมายเพื่อการเขียนโปรแกรมเชิงระบบ (system programming) เช่น รองรับการจัดการหน่วยความจำอย่างละเอียดโดยไม่ต้องใช้ตัวเก็บขยะ (garbage collection) และไม่ต้องจองหรือคืนหน่วยความจำด้วยมือซึ่งทั้งน่าเบื่อและเสี่ยงต่อข้อผิดพลาด อีกทั้งยังป้องกันการแข่งกันของข้อมูล (data race) ได้อีกด้วย

Rust บรรลุเป้าหมายนี้ด้วยระบบความเป็นเจ้าของ (ownership system) ซึ่งเกี่ยวข้องหลักๆ กับการตั้งชื่อแทนข้อมูล (variable aliasing) ณ จุดใดๆ ของโปรแกรม Rust คอมไพเลอร์จะติดตามว่ามีตัวแปรจำนวนเท่าใดที่อ้างอิงถึงข้อมูลหนึ่งๆ และบังคับใช้กฎชุดหนึ่งที่ทำให้เกิดการจัดการหน่วยความจำอัตโนมัติ ความปลอดภัยของหน่วยความจำ และโปรแกรมที่ปราศจาก data race

ภาษานี้ยังให้ความสำคัญกับประสิทธิภาพ ด้วยการปรับปรุงการคอมไพล์ที่ทรงพลังและโครงสร้างภาษาที่ช่วยให้เขียนโค้ดแบบ *zero-cost abstraction* ได้

ยิ่งไปกว่านั้น ภาษา Rust ยังมีฟีเจอร์การเขียนโปรแกรมระดับสูง ด้วยฟังก์ชันอันดับสูง (higher-order functions) โคลเชอร์ (closures) และอีเทอเรเตอร์ (iterators) เป็นต้น ช่วยให้เขียนบางส่วนของโปรแกรมในแนวทางเดียวกับภาษาเชิงฟังก์ชัน นอกจากนี้ วินัยของระบบชนิดข้อมูลแบบสถิต (static typing) การอนุมานชนิดข้อมูล (type inference) และพหุสัณฐานเฉพาะกิจ (ad hoc polymorphism ในรูปของเทรต) ก็เป็นอีกวิธีที่ Rust มอบให้เพื่อสร้างไลบรารีและโปรแกรมอย่างปลอดภัย

ท้ายที่สุด ชุดเครื่องมือ (rustup, cargo) ก็ช่วยอำนวยความสะดวกในการใช้ Rust เป็นอย่างมาก โดยลดความยุ่งยากของการตั้งค่าการสร้างซอฟต์แวร์ พร้อมทั้งให้น้ำหนักกับแนวปฏิบัติที่ดีด้านความปลอดภัยในการคอมไพล์

อย่างไรก็ตาม เนื่องจากความอเนกประสงค์ของภาษา Rust จึงอาจมีโครงสร้างบางอย่างที่หากใช้ไม่ถูกต้องก็สามารถก่อให้เกิดปัญหาด้านความปลอดภัยได้ โดยทำให้โค้ดถูกตีความผิดโดยผู้เขียนโปรแกรมหรือผู้ตรวจทาน นอกจากนี้ เช่นเดียวกับเครื่องมือทุกชนิดในด้านการคอมไพล์หรือการตรวจสอบซอฟต์แวร์ เครื่องมือที่ใช้พัฒนา คอมไพล์ และเรียกใช้โปรแกรมอาจเปิดเผยฟีเจอร์หรือการตั้งค่าบางอย่างที่หากใช้ผิดก็อาจนำไปสู่ช่องโหว่ได้

ดังนั้น วัตถุประสงค์ของเอกสารนี้จึงเป็นการรวบรวมคำแนะนำและข้อชี้แนะเพื่อให้อยู่ในพื้นที่ปลอดภัยสำหรับการพัฒนาแอปพลิเคชันที่ปลอดภัย โดยยังใช้ประโยชน์จากความเป็นไปได้ทั้งหมดที่ภาษา Rust มอบให้

## กลุ่มผู้อ่านเป้าหมาย

แนวทางนี้ตั้งใจรวบรวมข้อเสนอแนะที่ควรนำไปใช้สำหรับการพัฒนาแอปพลิเคชันที่มีข้อกำหนดด้านความปลอดภัยระดับสูง อย่างไรก็ตาม ทุกคนที่ต้องการมั่นใจว่าการรับประกัน (guarantees) ที่แพลตฟอร์ม Rust มอบให้ไม่ถูกลบล้างไปเพราะการใช้ฟีเจอร์อย่างไม่ปลอดภัย ชวนสับสน หรือไม่ชัดเจน ก็สามารถทำตามแนวทางนี้ได้

เอกสารนี้ไม่ได้ตั้งใจให้เป็นคอร์สสอนเขียนโปรแกรม Rust เพราะมีแหล่งเรียนรู้ที่ดีเพียงพออยู่แล้วสำหรับจุดประสงค์นั้น (ตัวอย่างเช่น [หน้าหลักเอกสาร Rust](https://doc.rust-lang.org)) จุดประสงค์คือการแนะนำนักเขียนโปรแกรมและแจ้งให้ทราบถึงข้อควรระวัง (pitfalls) ที่อาจพบเจอ ข้อเสนอแนะเหล่านี้เป็นส่วนเสริมต่อความน่าเชื่อถือที่ดีที่ภาษา Rust มอบให้อยู่แล้ว กล่าวคือ บางครั้งการทบทวนซ้ำก็จำเป็นเพื่อความชัดเจน และนักเขียนโปรแกรม Rust ที่มีประสบการณ์อาจใช้เพียงกล่องข้อความเน้น (*กฎ*, *ข้อเสนอแนะ*, *คำเตือน* เป็นต้น) เท่านั้นก็ได้

## โครงสร้างของเอกสาร

เอกสารนี้พิจารณาระยะต่างๆ ของกระบวนการพัฒนาซอฟต์แวร์ทั่วไป (และแบบย่อ) แยกออกจากกัน เริ่มแรก เราให้คำแนะนำเกี่ยวกับวิธีใช้ประโยชน์จากเครื่องมือในระบบนิเวศ Rust เพื่อการพัฒนาที่ปลอดภัย พร้อมทั้งข้อควรระวังในการเลือกและใช้งานไลบรารีภายนอก จากนั้นจึงนำเสนอข้อเสนอแนะเกี่ยวกับโครงสร้างภาษา Rust

สุดท้าย เราขอนำเสนอข้อเสนอแนะบางประการสำหรับไลบรารี Rust ที่มีอยู่แล้ว

โปรดทราบว่า Rust แบบ *async* (ดู [Asynchronous Programming in Rust @rust-async]) ยังไม่ถูกกล่าวถึงในเอกสารนี้ในปัจจุบัน

สรุปข้อเสนอแนะทั้งหมดที่นำเสนอในเอกสารนี้รวบรวมไว้ที่ตอนท้ายของแนวทางนี้

## สัญลักษณ์และข้อกำหนดในการอ่าน

สำหรับข้อเสนอแนะแต่ละข้อในแนวทางนี้ การใช้คำกริยา *must* จงใจให้มีน้ำหนักบังคับมากกว่าถ้อยคำ *it is recommended*

เมื่อพิจารณาภัยคุกคามที่ระบุระหว่างการร่างแนวทางนี้ สำหรับข้อเสนอแนะบางข้อมีการเสนอวิธีแก้หลายทางซึ่งแตกต่างกันตามระดับความปลอดภัยที่มอบให้ ผู้อ่านจึงสามารถเลือกวิธีที่ให้การป้องกันดีที่สุดตามบริบทและวัตถุประสงค์ด้านความปลอดภัยของตน
