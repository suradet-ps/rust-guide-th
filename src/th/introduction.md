# บทนำ

[Rust](https://www.rust-lang.org) เป็นภาษาหลายกระบวนทัศน์ (multi-paradigm) ที่มุ่งเน้นความปลอดภัยของหน่วยความจำ (memory safety)

ภาษานี้มุ่งเน้นการเขียนโปรแกรมเชิงระบบ (system programming) ตัวอย่างเช่น ช่วยให้จัดการหน่วยความจำได้อย่างละเอียดโดยไม่ต้องใช้ตัวเก็บขยะ (garbage collection) และไม่ต้องจองหรือคืนหน่วยความจำด้วยตนเองซึ่งทั้งน่าเบื่อและเสี่ยงต่อข้อผิดพลาด ตลอดจนช่วยป้องกันการแข่งกันของข้อมูล (data race) ได้อีกด้วย

Rust บรรลุเป้าหมายนี้ด้วยระบบความเป็นเจ้าของ (ownership system) ซึ่งเกี่ยวข้องหลัก ๆ กับการตั้งชื่อแทนข้อมูล (variable aliasing) ณ จุดใด ๆ ของโปรแกรม Rust คอมไพเลอร์จะติดตามว่ามีตัวแปรกี่ตัวที่อ้างอิงถึงข้อมูลชุดเดียวกัน และบังคับใช้กฎชุดหนึ่งที่ทำให้เกิดการจัดการหน่วยความจำอัตโนมัติ ความปลอดภัยของหน่วยความจำ และโปรแกรมที่ปราศจากการแข่งกันของข้อมูล

ภาษานี้ยังให้ความสำคัญกับประสิทธิภาพ ด้วยการปรับแต่งการคอมไพล์ที่ทรงพลังและโครงสร้างภาษาที่ช่วยให้เขียนโค้ดแบบ *zero-cost abstraction* ได้

ยิ่งไปกว่านั้น ภาษา Rust ยังมีฟีเจอร์การเขียนโปรแกรมระดับสูง ด้วยฟังก์ชันอันดับสูง (higher-order functions) คลอเชอร์ (closures) และอีเทอเรเตอร์ (iterators) เป็นต้น จึงช่วยให้เขียนบางส่วนของโปรแกรมได้ในแนวทางเดียวกับภาษาเชิงฟังก์ชัน นอกจากนี้ การกำหนดชนิดแบบสถิตอย่างเคร่งครัด (static typing) การอนุมานชนิดข้อมูล (type inference) และพหุสัณฐานเฉพาะกิจ (ad hoc polymorphism) ในรูปของเทรต (trait) ก็เป็นอีกวิธีที่ Rust มอบให้เพื่อสร้างไลบรารีและโปรแกรมอย่างปลอดภัย

ท้ายที่สุด ชุดเครื่องมือ (rustup, cargo) ก็ช่วยอำนวยความสะดวกในการใช้ Rust เป็นอย่างมาก โดยลดความยุ่งยากในการตั้งค่าการสร้างซอฟต์แวร์ พร้อมทั้งให้ความสำคัญกับแนวปฏิบัติด้านความปลอดภัยในการคอมไพล์ที่ดี

อย่างไรก็ตาม เนื่องจากความอเนกประสงค์ของภาษา Rust จึงอาจมีโครงสร้างบางอย่างที่หากใช้ไม่ถูกต้องก็สามารถก่อให้เกิดปัญหาด้านความปลอดภัยได้ โดยอาจทำให้ผู้เขียนโปรแกรมหรือผู้ตรวจทานตีความโค้ดผิดไป นอกจากนี้ เช่นเดียวกับเครื่องมือทุกชนิดในด้านการคอมไพล์หรือการตรวจสอบซอฟต์แวร์ เครื่องมือที่ใช้พัฒนา คอมไพล์ และเรียกใช้โปรแกรมอาจเปิดให้ใช้ฟีเจอร์หรือการตั้งค่าบางอย่าง ซึ่งหากใช้ผิดอาจนำไปสู่ช่องโหว่ได้

ดังนั้น วัตถุประสงค์ของเอกสารนี้จึงเป็นการรวบรวมข้อชี้แนะและข้อเสนอแนะเพื่อให้อยู่ในพื้นที่ปลอดภัยสำหรับการพัฒนาแอปพลิเคชันที่ปลอดภัย โดยยังใช้ประโยชน์จากความเป็นไปได้อันหลากหลายที่ภาษา Rust มอบให้

## กลุ่มผู้อ่านเป้าหมาย

แนวทางนี้มีจุดมุ่งหมายเพื่อรวบรวมข้อเสนอแนะที่ควรนำไปใช้สำหรับการพัฒนาแอปพลิเคชันที่มีข้อกำหนดด้านความปลอดภัยระดับสูง อย่างไรก็ตาม ทุกคนที่ต้องการมั่นใจว่าการรับประกัน (guarantees) ที่แพลตฟอร์ม Rust มอบให้ไม่ถูกลบล้างไปจากการใช้ฟีเจอร์อย่างไม่ปลอดภัย ทำให้เข้าใจผิด หรือไม่ชัดเจน ก็สามารถปฏิบัติตามแนวทางนี้ได้

เอกสารนี้ไม่ได้มีจุดมุ่งหมายให้เป็นคอร์สสอนเขียนโปรแกรม Rust เพราะมีแหล่งเรียนรู้ที่ดีเพียงพออยู่แล้วสำหรับจุดประสงค์นั้น (ตัวอย่างเช่น [หน้าหลักเอกสาร Rust](https://doc.rust-lang.org)) จุดประสงค์หลักคือการแนะแนวทางและแจ้งให้นักเขียนโปรแกรมทราบถึงหลุมพราง (pitfalls) ที่อาจพบเจอ ข้อเสนอแนะเหล่านี้เป็นส่วนเสริมต่อความน่าเชื่อถือที่ดีที่ภาษา Rust มอบให้อยู่แล้ว ถึงกระนั้น บางครั้งการทบทวนซ้ำก็จำเป็นเพื่อให้เกิดความชัดเจน และนักเขียนโปรแกรม Rust ที่มีประสบการณ์อาจใช้เพียงกล่องข้อความที่เน้น (*กฎ*, *ข้อเสนอแนะ*, *คำเตือน* เป็นต้น) เท่านั้นก็ได้

## โครงสร้างของเอกสาร

เอกสารนี้พิจารณาระยะต่าง ๆ ของกระบวนการพัฒนาซอฟต์แวร์ทั่วไป (และแบบย่อ) แยกออกจากกัน เริ่มแรก เราให้คำแนะนำเกี่ยวกับวิธีใช้ประโยชน์จากเครื่องมือในระบบนิเวศ Rust เพื่อการพัฒนาที่ปลอดภัย พร้อมทั้งคำแนะนำเกี่ยวกับข้อควรระวังในการเลือกและใช้งานไลบรารีภายนอก จากนั้นจึงนำเสนอข้อเสนอแนะเกี่ยวกับโครงสร้างภาษา Rust

สุดท้าย เราขอนำเสนอข้อเสนอแนะบางประการสำหรับไลบรารี Rust ที่ได้รับการยอมรับแล้ว

สรุปข้อเสนอแนะที่นำเสนอตลอดเอกสารนี้รวบรวมไว้ตอนท้ายของแนวทางนี้

## สัญลักษณ์และข้อกำหนดในการอ่าน

สำหรับข้อเสนอแนะแต่ละข้อในแนวทางนี้ การใช้คำกริยา *must* มีเจตนาให้เป็นข้อบังคับมากกว่าถ้อยคำ *it is recommended*

เมื่อพิจารณาภัยคุกคามที่ระบุระหว่างการร่างแนวทางนี้ สำหรับข้อเสนอแนะบางข้อมีการเสนอวิธีแก้หลายทางซึ่งให้ระดับความปลอดภัยแตกต่างกัน ผู้อ่านจึงสามารถเลือกวิธีที่ให้การป้องกันดีที่สุดตามบริบทและวัตถุประสงค์ด้านความปลอดภัยของตน
